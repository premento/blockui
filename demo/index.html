blockUI
running on jQuery

Blocking,not locking.

Put an overlay over the page, or over one element, while something is in flight. The browser stays responsive the whole time — nothing is frozen, the user just can’t reach what’s underneath.

This panel blocks itself in a moment.

Three layers, every time

Every block builds the same stack. Knowing which layer is which is most of what you need to style it.

  • .blockUI
    The iframe

    Optional, off by default. Turn on forceIframe when a plugin or embed paints straight over the overlay.

  • .blockOverlay
    The overlay

    The dimmed sheet that swallows clicks. Fixed for a page block, absolute for an element block.

  • .blockMsg
    The message

    Your content. Anything you can put in a string, a DOM node or a jQuery object goes here.

Try it

Every panel below is live. Each one runs exactly the code shown beside it.

Block the page

The default message is a spinner and a line of text. It clears itself after two seconds here.

Try scrolling or clicking while it’s up — the page is covered, but the browser never stops responding.

// the whole page
$.blockUI();

// ...and your own content
$.blockUI({ message: '<h3>Uploading</h3>' });

$.unblockUI();

Block one element

Same call, scoped to a selection. blockUI gives the element position: relative if it needs it, and puts it back afterwards.

Only this panel goes dim. The rest of the page stays live — scroll, click, switch the theme.

$('#panel').block({ message: 'Saving…' });

// overlay with no message at all
$('#panel').block({ message: null });

$('#panel').unblock();

A modal dialog

Pass something with a form control in it and blockUI marks the panel role="dialog", traps Tab inside it, and hands focus back to the button you came from.

Tab round it, then close with Escape. Focus returns to the button that opened it.

$.blockUI({
	message: $('#myForm'),
	escapeToUnblock: true,
	onOverlayClick: $.unblockUI
});

Growl notices

A small toast in the corner, with no overlay. Hover it and it waits for you.

The page stays entirely usable — growl notices never block anything.

$.growlUI('Deployed', 'build 4821 is live');

Restyle it

Pass css and overlayCSS for one call, or set them on $.blockUI.defaults for all of them. The old pre-2.80 look is still in the box.

Styles passed to a call always win, stylesheet or not.

$.blockUI({
	css: { backgroundColor: '#16202c', color: '#fff' },
	overlayCSS: { backgroundColor: '#e8a317' }
});

// bring back the original styling wholesale
$.blockUI.defaults.css = $.blockUI.classicCSS;

What’s new in 2.80

Options added or changed in the jQuery 4 port. Everything else from 2.70 works as it did.

OptionDefaultWhat it does
escapeToUnblock new false Close the block when the user presses Escape. Leave it off for progress blocks the user must not dismiss.
restoreFocus new true Return focus to whatever had it before the page was blocked.
ariaRole new 'auto' 'dialog' when the message holds something focusable, otherwise a polite 'status' region. Pass your own, or null for none.
respectReducedMotion new true Skip the fades when the OS asks for reduced motion.
autoDetectCSS new true Drop the built-in inline styling when jquery.blockUI.css is on the page, so the stylesheet wins without !important.
injectCSS new true Add the spinner keyframes, which an inline style can’t express. Turn it off under a strict style-src policy.
message changed spinner + text Was <h1>Please wait...</h1>. The old one is $.blockUI.classicMessage.
css, overlayCSS changed see source Restyled. $.blockUI.classicCSS and classicOverlayCSS restore the originals.
forceIframe changed false The iframe layer used to appear automatically in IE. Now it only appears when you ask for it.
allowBodyStretch, quirksmodeOffsetHack — No-ops now. They only ever applied to IE 6/7 quirks mode; kept so existing config objects don’t break.
